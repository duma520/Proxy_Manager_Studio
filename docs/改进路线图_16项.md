## 二、逐条方案

### A 档 — 性能 / 校验 / 真 bug（低风险，单文件为主，建议优先）

**3. `pms_format_bytes` 缓存 / 查表**
- 现状：`utils.py:45-59`，每次调用都 `while value>=1024: value/=1024; index+=1` 再 f-string。
- 方案：① 用 `functools.lru_cache`（按 `int(bytes)` 做键，流量面板多为整数累计值）；② 或预计算 0~1GiB 分段查表。注意入参是 `float` 且可能为累计值，缓存键取 `int(round(value))` 即可覆盖 99% 场景。
- 风险：低。验证：写一个微基准，1 万次调用耗时对比；确保返回值与现有一致（含负值/`-/B` 分支）。

**5. `pms_b64_decode_loose` 流式解码**
- 现状：`utils.py:368-380`，`base64.b64decode(raw).decode(...)` 一次性成串。
- 方案：`base64` 模块支持分块增量解码（`base64.b64decode` 带 `validate` 或自写 4 字符对齐分块），对 5MB 订阅按 4n 字符切片增量解，峰值从「输入+全量输出」降为「输入+单块」。若实现成本高，至少用 `io.BytesIO` + `base64.decode` 增量写出到内存视图，避免中间大串。
- 风险：低（base64 对齐需小心，单测覆盖非 4 倍数、含 `=` padding）。验证：5MB base64 订阅解码结果与原实现逐字节一致，峰值内存下降。

**7. `pinnedPeerCertSha256` 十六进制校验**
- 现状：`coreconfig.py:288` 直接 `tls_settings["pinnedPeerCertSha256"]=node.cert_sha256`；编辑框无校验。
- 方案：在 `nodeeditor.py` 保存时校验→规范化：`re.fullmatch(r'([0-9a-fA-F]{2}:?){31}[0-9a-fA-F]{2}', raw)` 去冒号/空格/小写，得 64 位 hex；非法则红框提示且不存。校验函数放 `utils.py` 复用（Xray/V2Ray 共用）。
- 风险：低。验证：输入 `AB:CD…` / 带空格 / 大写 / 少一位 → 规范化结果与拒绝分支单测。

**8. Hysteria2 `obfs` 白名单校验**
- 现状：`coreconfig.py:745-747` `psc_build_obfs` 不校验取值；Hysteria2 仅认 `salamander`。
- 方案：① 编辑框改为下拉（`salamander` / 无）；② 或保存时白名单校验，非 `salamander` 且非空则拦截。生成端 `psc_build_obfs` 加断言兜底（非法直接返回 `{}` 并记日志）。
- 风险：低。验证：填 `tls`/`http` → 被拦；填 `salamander` → 正常生成。

**9. WireGuard `reserved` 漏写（真 bug，优先修）**
- 现状：导入 `sharelinks_extra.py:218` 存 `reserved`（形如 `1,2,3`）；生成 `coreconfig.py:657-663` **未写回**。
- 方案：在 `coreconfig.py` WireGuard outbound 分支读取 `extra["reserved"]`，按逗号/空格拆分→`[int(x) for x in ...]`→`outbound["reserved"]=[1,2,3]`；空或非法则跳过并记日志。
- 风险：中（连不上的真实原因）。验证：导入 WARP 链接 → 生成配置含 `reserved:[1,2,3]` → 实测可连。

**10. Snell `obfs` 版本校验**
- 现状：编辑框自由输入；需核对 `coreconfig.py` Snell 分支与 `sharelinks_extra.py:170-196` Snell 解析。
- 方案：按 Snell `version` 限定 `obfs` 取值（v4→`http`，v5→`tls`），保存时校验；跨协议导入带错值则归一。
- 风险：低。验证：v4 填 `tls` 被拦；v5 填 `http` 被拦。

**4. 日志正则预编译（已满足，仅复核）**
- 结论：`logparse.py:39/47/52` 已是模块级 `re.compile()`，函数内无 `re.match/search` 重复编译。无需改。

### B 档 — 协议正确性与导入健壮性（需核对后小改）

**6. `spider_x` 是否写进核心（已核对，落实结论）**
- 结论：Xray Reality 已写 `spiderX`（`coreconfig.py:297`）；sing-box 因 1.14.x 移除 `tls.reality.spider_x` 而**刻意不写**（`coreconfig.py:770-771`，写了会整体解析失败）。
- 行动：确认你目标 sing-box 版本是否仍移除该字段；若是，维持现状并补注释说明；若升级到重新支持的版本，再放开。无需改代码，需留痕到《升级迭代记录》。

**11. 订阅 header 解析失败留存原始串**
- 现状：需核对 `sharelinks.py` / `importers.py` / `telegramimport.py` 的 header 解析分支（不同机场 `expire=`/`reset_day=` 差异）。
- 方案：解析失败时不只显示「未知」，把原始 header 串存到节点 `extra_json` 的 `_raw_subscription_header` 字段 + 记日志，便于排查；成功解析的字段照常填充。

### C 档 — 新功能（先出架构方案再编码）

**1. 便携模式 `--portable`**
- 涉及：`Proxy_Manager_Studio.py`（argparse 解析 `--portable`）→ 传给 `PmsSettingsManager`（`settings.py:88` 路径）与核心数据目录解析（`prt_data_dir`，见 `latency.py:288`）。
- 方案：`--portable` 时数据目录 = `exe 同级目录/.pms_portable/`（或 `exe 目录`），`pms_settings.json`、订阅库、核心缓存全部跟随；否则维持当前（用户目录/CWD）。需统一一个「路径解析入口」避免散落。
- 风险：中。验证：U 盘根目录运行，`--portable` 后所有写盘落在 exe 旁，拔出后无残留。

**12. API 依赖健康检查**
- 涉及：`api.py:168` `papi_health` + `apiserver.py:494`。
- 方案：扩展 `papi_health` 返回 `{status, core_running, db_writable, settings_ok, version}`；`core_running` 复用 `papi_status` 逻辑，`db_writable` 做一次轻量写回滚，`settings_ok` 复用 `psm_normalize` 结果。脚本单端点即可判断健康。
- 风险：低。

**13. 升级迁移检查**
- 涉及：`settings.py:130` `psm_normalize` + `database.py`（需核对是否有 schema 版本字段）。
- 方案：启动时读设置/DB 的 `schema_version`；低于当前则执行对应迁移脚本（设置补键、DB ALTER），并提示用户「已从 vX 迁移到 vY」。迁移脚本放 `_scaffold/migrations/` 或 `pms/migrations.py`。
- 风险：中（数据安全，必须先备份再迁移）。

**14. 网络诊断工具**
- 涉及：新 GUI 面板 + 诊断逻辑（本机网络 / 代理端口 / 核心进程 / 目标网站，分步定位）。
- 方案：复用现有 `PmsCoreLaunchProfile`、端口探测 `pms_find_free_port`、核心进程句柄；分步出「是否能上网→代理端口通不通→核心起没起→目标站通不通」，每步给结论+建议。

**15. 设置历史 / 配置对比**
- 涉及：`settings.py` 存盘钩子 + 新 GUI + 快照存储（SQLite 或 JSON 增量）。
- 方案：每次「应用设置」前存一份快照（diff 友好），提供列表+回滚+两版对比。

### D 档 — 架构重构（高风险，单独成任务）

**2. Xray 单核心多出站批量测速**
- 现状：`latency.py:265-278` 批量测速已对 sing-box 实现「单核心 + 多 outbound + 单 mixed inbound + Clash API」；Xray 走 `use_clash` 之外的逐节点临时核心路径。
- 方案：为 Xray 核心写等价批量配置——单 Xray 进程放 N 个 outbound（每节点一个 tag）+ N 个 socks/inbound 端口或单 inbound 多 tag + 路由按 tag 分流；并发量用 `Semaphore` 限流，复用现有 `QThreadPool` 并发模型。预期提速同 sing-box 快通道。
- 风险：高（Xray 配置 schema 与 sing-box 不同，需逐协议验证 outbound 生成）。验证：同批节点，Xray 批量 vs 旧逐节点，耗时对比 + 结果一致率。

**16. 插件 / 适配器注册机制**
- 涉及：`coreconfig.py` 硬编码的协议→核心规格表。
- 方案：把「内核规格」抽成适配器接口（同一套 `build_outbound/build_inbound/validate`），从 `pms/adapters/*.json`（或 py 注册表）读取；新增内核只需加一个适配器文件，不改主程序。
- 风险：高（重构面大，需保证现有 9+ 协议行为不变）。
